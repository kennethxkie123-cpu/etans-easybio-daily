LayerHub System Analysis & Technical Architecture

1. System Overview & Technology Stack

LayerHub is a production-grade, local-first Flutter Desktop ERP application engineered specifically for commercial layer poultry farms. It maintains 100% offline functionality using an embedded SQLite engine via Drift ORM with sub-100ms calculation benchmarks.

Framework: Flutter Desktop (Windows target) Database Engine: SQLite (via Drift ORM, Schema v19) Concurrency Strategy: BackgroundIsolates & LRU Caching PRAGMA Configuration: WAL Journal Mode, Synchronous NORMAL, Foreign Keys ON

2. Entity Relational Schema

The system tracks multi-flock lifecycles, egg production, grading classifications, mortality causes, medication regimes, and environmental metrics.

Buildings (id, farmId, name, capacity, status, assignedFlokman) └─► Flocks (id, buildingId, birdCount, startDate, strain, ageAtLoadingWeeks, isActive) ├─► DailyRecords (date, currentHeads, mortalities, culls, cases, trays, totalPieces, defects, feedBags, weather) ├─► EggSizeRecords (date, eggSizeName, cases, trays, pieces, totalPieces) ├─► Mortalities (date, count, reason) └─► Medications (date, medicineName, dosage, notes)

3. Core Calculation Formulas

Key production metrics are calculated continuously across isolate boundaries:

  • Hen-Day Laying Rate (%): (Total Egg Pieces / (Current Heads + Daily Mortalities + Culls)) * 100
  • Feed Intake (g/bird): (Feed Bags * 50kg * 1000g) / Current Heads
  • Feed Conversion Ratio (FCR): Total Grams Consumed / (Total Egg Pieces * Standard Egg Weight (g))
  • Egg Combinations (Butal Math): 1 Case = 12 Trays = 360 Eggs, 1 Tray = 30 Eggs

4. Security & Audit Trail

LayerHub incorporates Role-Based Access Control (RBAC with Admin, Manager, and Viewer roles) and logs every critical insert, update, or delete in an immutable AuditLogs table.
